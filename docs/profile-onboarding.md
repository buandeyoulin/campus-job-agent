# 资料工作台

资料工作台用于在本机维护一位候选人的基本信息、求职偏好、简历和可复用的经历事实。当前阶段不会检索职位、定制简历或提交职位申请。

## 启动方式

需要 Node.js 24.15.0 或更高版本。在 Windows PowerShell 中运行：

```powershell
npm install
npm run dev
```

浏览器界面位于 `http://127.0.0.1:4318`，本地 API 位于 `http://127.0.0.1:4317`。服务只绑定回环地址，不应暴露到局域网或公网。

Codex 是默认 AI 提供方。开始 AI 提取前，可在终端检查本机登录状态：

```powershell
npm exec -- codex login status
```

## 数据保存位置与 CAMPUS_JOB_AGENT_DATA_DIR

Windows 默认数据目录是 `%LOCALAPPDATA%\CampusJobAgent`。其中包括 SQLite 数据库、原始简历、解析文本、迁移备份和生成文件目录。它们不保存在 Git 仓库内。

可以在启动前指定独立目录：

```powershell
$env:CAMPUS_JOB_AGENT_DATA_DIR = "C:\temp\campus-job-agent-data"
npm run dev
```

请勿把数据目录设置到公开同步目录或 Git 仓库。更改环境变量只影响随后启动的进程。

## 基本信息与求职偏好

先保存姓名或称呼，才能保存求职偏好和上传简历。邮箱、手机号、城市、学历、专业、毕业月份以及岗位、城市、招聘类型、实习时间和公司偏好都保存在本地 SQLite 中。基本信息和求职偏好独立保存：某一张卡片保存失败时，不会覆盖另一张卡片已经保存的内容。

Phase 1 不会把这些表单字段单独发送给 AI。

## 手动维护核心事实

无需上传简历即可维护教育、实习、项目和技能事实。手工创建的事实也需要明确确认后，才计入资料完成度。建议只记录能够在面试或证明材料中说明的内容，不要为了匹配岗位虚构经历。

## 上传 PDF/DOCX 简历

仅接受扩展名、MIME 类型和文件签名一致的 PDF 或 DOCX，每个文件最大 10 MiB。服务使用随机 UUID 文件名写入数据目录，不使用上传文件名拼接磁盘路径。相同内容按 SHA-256 去重，再次上传只会重新激活已有记录。

上传只完成本地持久化，不会自动启动 AI。原文件保存在 `resumes\original`，解析后的 UTF-8 文本保存在 `resumes\parsed`。

## Codex 处理前的明确确认

只有勾选“我了解脱敏后的简历文本会发送给所选 AI 提供方处理”并点击“开始 AI 提取”后，应用才会解析简历并调用 AI。上传、替换或重新打开页面不会代替这次明确确认。

默认 Codex 运行在独立的临时空 Git 目录中，使用只读沙箱、禁止审批、禁用网络工具和 Web 搜索，并关闭本地 Codex 历史持久化。模型请求本身仍会离开本机，并受登录工作区的服务和数据政策约束。

## 脱敏边界与仍然存在的隐私风险

发送前会尽力把以下模式替换为占位符：

- 邮箱地址；
- 中国大陆手机号（含常见 `+86` 写法）；
- 18 位中国居民身份证号。

AI 收到的文本仍可能包含姓名、学校、公司、城市、日期、教育背景、实习经历、项目经历、技能、成果描述以及其他自由文本。正则脱敏无法识别所有格式，也不能保证匿名化；地址、学号、证书编号、作品链接和罕见联系方式可能仍然存在。请在确认前自行评估简历内容和所选 AI 提供方的政策。

原始 PDF/DOCX、基本资料表单和求职偏好不会作为 Phase 1 的 AI 请求附件发送；发送的是尽力脱敏后的解析文本。

## 候选事实的确认、拒绝与去重提示

AI 提取的事实默认是“待确认”，不会直接成为已确认事实。可以逐条编辑、确认、拒绝或删除，也可以只勾选需要的待确认事实后批量确认。

完全相同的事实会跳过。可能相似的事实会同时展示“候选事实”和“可能重复的已有事实”，由用户判断；系统不会自动覆盖或合并已经确认的事实。

## 失败恢复、重试与删除

解析失败、空文本、AI 调用失败、AI 输出格式无效或进程中断时，界面只显示稳定错误和恢复入口，不暴露底层异常。原始简历会保留。AI 阶段失败时，已经成功保存的解析文本也会保留，重试不必重新上传或解析。

启动时会把上次处于排队、解析或提取中的记录标记为“已中断”，之后可以手动重试。AI 调用失败时，可运行 `npm exec -- codex login status` 检查登录状态，但登录不是所有失败的唯一原因。

删除简历会删除对应的原文件、解析文本和未确认事实。已经确认的事实会保留在本地资料库中，但解除与已删除简历的来源关联。

## 数据库备份和手工导出目录

数据库文件是数据根目录中的 `data.sqlite`。未来有待执行的数据库迁移时，应用会先在 `backups` 目录创建迁移前备份，再修改数据库。备份不是持续同步或灾难恢复方案，重要资料仍应由用户自行备份整个数据根目录。

`generated` 是后续简历、面试材料和手工导出的预留目录；Phase 1 尚未提供自动导出按钮。不要在应用运行且数据库正在写入时只复制单个 SQLite 文件，优先停止应用后备份完整数据目录。

## Phase 1 不会自动投递职位

Phase 1 不会登录招聘网站、点击申请、填写外部表单、发送邮件或替用户提交任何职位申请。所有投递保持手动。职位发现、匹配、定制简历和面试准备属于后续阶段，启用前需要单独设计和确认。
