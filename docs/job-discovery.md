# 公开岗位发现与数据边界

## 岗位从哪里来

岗位只来自公开、无需凭据的网页或接口：

1. 已核验公司官网链接的招聘入口，优先使用 JSON-LD、明确的官方 JSON 映射或仓库内固定的 HTML 选择器。
2. 已支持的直接公开来源。
3. 用户明确提交的公开岗位 JSON。

搜索引擎结果只用于发现候选公司。候选公司必须经过官网身份、HTTPS 跳转链和招聘入口证据核验，才能进入公司库；搜索结果本身不会直接生成岗位。

## 本机保存与去重

默认 SQLite 数据目录为 `%LOCALAPPDATA%\CampusJobAgent`，可通过 `CAMPUS_JOB_AGENT_DATA_DIR` 覆盖。岗位保存公开 URL、来源岗位 ID、抓取时间、公司和招聘来源关联。重复同步会更新已有岗位，而不是不断新增副本。

完整扫描连续两次未发现某岗位时，岗位状态才从 `active` 变为 `possibly_expired`，再变为 `closed`。部分扫描、来源失败或尚无适配器都不会关闭已有岗位。

## 网络边界

- 仅访问无需登录的公开 HTTP(S) 信息；官方岗位同步要求 HTTPS。
- 不保存 Cookie、登录令牌、认证头或外部网站凭据。
- 单页响应限制为 2 MiB，限制重定向次数并设置超时。
- 来源失败相互隔离，并采用最长 7 天的指数退避。
- 未配置解析适配器的来源会显示为“跳过”，不会被误判为故障。

## 人工投递边界

应用只提供普通的公开岗位链接。不会自动打开并操作申请页面，不会登录、填写表单、发送邮件或提交申请。最终投递始终由用户在公司官网手动完成。
