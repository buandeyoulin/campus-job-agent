# 自建芯片公司库与官方岗位源设计

## 目标

彻底删除仓库中旧聚合数据源的代码、扩展、接口、测试、数据结构、文档和历史引用，改为由 Campus Job Agent 自己维护公司库。系统以内置芯片/半导体公司种子库保证开箱可用，同时通过可选搜索 API 自动发现新公司，并且只从已验证的公司官网或官方 ATS 获取岗位。

最终投递始终由用户手动完成。系统只负责公司发现、官网验证、岗位同步、AI 匹配、定制简历、面试准备和求职进度跟踪。

## 已选方案

采用“ATS 优先 + 通用官网解析 + 少量专用适配器”：

1. 内置芯片/半导体公司种子库。
2. 搜索 API 自动发现候选公司和招聘入口。
3. 系统根据多重公开证据自动确认公司身份，无需用户逐条审批。
4. 证据充分的公司进入正式库；不确定候选进入隔离区并定期重试。
5. 正式公司按 ATS API、官网 JSON API、JSON-LD、站点地图、HTML 列表和专用适配器的优先级同步岗位。

不采用以下方案：

- 为每家公司永久维护一个独立爬虫：覆盖越大，维护成本越不可控。
- 使用通用浏览器 AI 作为日常主抓取器：速度、成本、稳定性和完整性证明均不足。
- 抓取搜索结果网页：容易触发验证码并依赖不稳定页面结构；自动发现必须使用正式 API 或明确允许的公开数据源。
- 从招聘聚合网站复制公司库或岗位库：来源边界和持续可用性不可控。

## 系统架构

```text
内置芯片公司种子库
          │
搜索 API 自动发现新公司
          ▼
公司身份与官网自动验证
    ├─ 可信 → 正式公司库
    └─ 不确定 → 隔离区，定期重试
          │
          ▼
招聘入口与 ATS 类型识别
          │
          ▼
官方 ATS / JSON API / JSON-LD / 招聘页面适配器
          │
          ▼
标准化、去重、过期检测
          │
          ▼
本机岗位库 → AI 匹配 → 定制简历 / 面试准备
```

## 公司库数据模型

### `company_candidates`

保存尚未成为正式公司的发现结果：

- 候选名称、别名和发现时间。
- 搜索查询、结果 URL 和证据摘要。
- 推测官网主域名和招聘入口。
- 自动验证分数、状态和失败原因。
- 下次重试时间及重试次数。

候选状态为 `pending`、`quarantined`、`verified` 或 `rejected`。隔离候选不参与岗位同步。

### `companies`

保存通过自动验证的正式公司：

- 规范名称、别名和官网主域名。
- 行业标签、芯片细分方向和主要地区。
- 来源类型：`seed` 或 `discovery`。
- 验证分数、验证证据和最近验证时间。
- 当前状态：`active`、`paused` 或 `invalid`。

公司以规范主域名为主要唯一键，名称和别名用于合并同一主体，避免同名公司互相覆盖。

### `company_career_sources`

一个公司可以有多个招聘来源：

- 入口 URL 和规范来源 URL。
- 来源类型：`ats_api`、`json_api`、`json_ld`、`sitemap`、`html` 或 `custom`。
- ATS 类型和适配器标识。
- 最近成功、最近失败和最后完整同步时间。
- 连续失败次数、退避截止时间和健康状态。
- 发现与验证证据。

### 岗位记录

沿用通用岗位库，并确保每条岗位保留：

- 公司 ID、官方来源 URL 和来源岗位 ID 或稳定指纹。
- 标题、地点、招聘类型、JD、发布时间和截止时间。
- 首次发现、最后确认和最后变更时间。
- 状态：`active`、`possibly_expired` 或 `closed`。
- 抓取适配器和来源验证证据。

## 内置种子库

第一版种子库聚焦芯片与半导体行业，覆盖：

- CPU/GPU、AI 芯片、通信、MCU、模拟/射频、存储等芯片设计公司。
- 晶圆制造、封装测试、EDA、半导体设备和材料公司。
- 在中国公开招聘的国际半导体公司。
- 数字 IC、验证、DFT、后端、模拟 IC、FPGA、嵌入式、工艺和设备等目标岗位方向。

种子条目只包含公司身份、官网和经过核验的招聘入口，不复制岗位内容。种子数据进入仓库并可审查、可测试、可重复导入；重复运行不会创建重复公司。

## 自动发现

定义可替换的 `CompanyDiscoveryProvider`，使发现流程不绑定单一供应商。第一版默认实现 Brave Search API；密钥从本机环境变量读取，不写入仓库、SQLite、前端响应或日志。没有密钥时，种子导入和官方岗位更新仍正常工作，只跳过新公司发现。

选择 Brave 的原因：它提供正式 JSON Web Search API、国家和语言过滤、分页及明确的限流响应。Bing Search API 已于 2025 年退役；Google Custom Search JSON API 已停止接受新客户，因此两者不作为默认方案。

参考：

- [Brave Web Search API](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started)
- [Brave API authentication](https://api-dashboard.search.brave.com/documentation/guides/authentication)
- [Brave API rate limiting](https://api-dashboard.search.brave.com/documentation/guides/rate-limiting)
- [Microsoft Bing Search API retirement](https://learn.microsoft.com/en-us/lifecycle/announcements/bing-search-api-retirement)
- [Google Custom Search JSON API availability](https://developers.google.com/custom-search/v1/overview)

发现查询围绕芯片细分方向、地区、校园招聘、招聘官网和常见 ATS 组合生成。搜索结果仅产生候选记录，不直接产生岗位。

## 自动验证与隔离

验证器使用独立证据累计置信度：

- 候选域名、公司规范名称和公开品牌一致。
- 官网主页、关于页面和招聘页面的公司身份一致。
- 招聘入口属于官网域名、官网子域名，或由官网明确链接到官方 ATS 租户。
- 页面包含招聘、职位、校园招聘等明确语义。
- TLS、重定向链和最终来源 URL 有效。
- 排除招聘聚合站、猎头站、论坛、网盘、个人页面和无法归属公司的 ATS 租户。

只有达到可信阈值的候选才能进入正式库。证据不足、互相冲突或暂时无法访问的候选进入隔离区，按退避策略重新验证；隔离候选永不触发岗位抓取。

系统自动完成确认，不要求用户逐条审批。所有自动判断必须保存可读的证据和原因，便于后续审计。

## 官方岗位同步

适配器按以下顺序探测和使用：

1. 官方 ATS 公开接口。
2. 公司招聘官网公开 JSON API。
3. `JobPosting` JSON-LD。
4. 招聘站点地图和公开 HTML 列表。
5. 少量重点公司的专用适配器。
6. AI 浏览器解析只用于发现入口和识别页面结构，不参与日常主同步。

第一批通用适配器优先覆盖具有稳定公开结构、且在种子公司中实际出现频率较高的 ATS；不为尚未发现的供应商提前实现适配器。

同步遵守公开访问规则和速率限制。遇到 429、验证码、登录要求或明确访问限制时立即退避，不绕过限制。活跃招聘源默认每日检查，长期无岗位来源默认每周检查。

## 去重、变更和过期

- 首选官方来源岗位 ID；缺失时使用公司、标题、地点和 JD 的稳定指纹。
- 同一公司的多个官方入口出现相同岗位时合并来源，不重复创建。
- 每次同步记录新建、更新、未变化、疑似关闭和失败数量。
- 一次访问失败只更新来源健康状态，不改变岗位状态。
- 只有官方来源被成功完整读取且岗位消失，或官方明确标记关闭时，才累计关闭证据。
- 达到连续成功缺失阈值后，岗位先进入 `possibly_expired`，再次确认后进入 `closed`。

## 用户功能

公司库页面提供：

- 正式公司、隔离候选和招聘源健康状态。
- 行业、芯片细分方向、地区和关键词筛选。
- 公司最近验证时间、最近同步时间、岗位数量和官方招聘链接。
- 自动确认依据、失败原因和重试时间。
- “发现新公司”和“更新官方岗位”操作。
- 手动补充公司官网或招聘入口，但正常使用不依赖手工维护。

岗位库继续支持 AI 筛选、匹配解释、定制简历、面试问题生成和求职进度跟踪。任何岗位投递、表单填写和提交动作均由用户手动完成。

## 失败与恢复

- 搜索密钥缺失：跳过发现并显示配置提示，不影响种子库和岗位更新。
- 搜索额度耗尽或 429：遵循返回的重置时间退避，不重复消耗额度。
- 公司验证失败：进入隔离区，不进入正式库。
- 单个招聘源失败：记录健康状态并退避，不中断其他来源。
- 页面结构变化：适配器报告结构不匹配，不把空结果解释为岗位全部关闭。
- 数据库写入失败：当前批次回滚，已完成批次保持幂等并可安全重放。

## 彻底删除旧数据源

仓库必须完全剔除旧聚合数据源，不保留任何历史痕迹：

- 删除相关浏览器扩展、运行时代码、接口、适配器和依赖。
- 删除相关契约、错误码、前端操作和数据来源分支。
- 删除相关测试、测试数据、设计文档、实施计划、可行性报告和使用文档。
- 修改通用文档、脚本和报告，删除所有名称、域名和说明。
- 清理种子数据和本机迁移逻辑中的专属来源值。
- 完成后对整个版本控制仓库执行大小写不敏感扫描；旧来源名称和域名必须零匹配。

通用的公司库、公司招聘入口、岗位库、AI 匹配、简历、面试准备和求职跟踪能力保留并用于新架构。

## 测试与验收

- 全仓库旧来源名称和域名扫描为零匹配。
- 种子库可重复导入，正式公司数量稳定且不重复。
- 同域名不同名称会合并；不同域名同名公司不会错误合并。
- 搜索候选经过验证后只能进入正式库或隔离区。
- 隔离候选不能触发岗位同步。
- 非官网、聚合站和无法归属的 ATS 租户不能进入正式公司库。
- 无搜索 API 密钥时，种子库和官方岗位更新仍可工作。
- 适配器只接受已验证公司的官方来源。
- 单源失败、限流或页面变化不会导致岗位误关闭，也不影响其他公司。
- 重复同步不会创建重复岗位。
- 所有类型检查、测试、构建和差异检查通过。
- 应用没有自动投递、表单填写或提交能力。
