# Phase 2：公开职位发现设计

## 状态与范围

本设计由用户授权代理自行决策后确定。它实现校园招聘与实习岗位的第一个可用闭环：从公开来源获取岗位、保存可审计的原始快照、规范化与去重，并在本地界面中查看。

本阶段不实现自动投递、登录招聘网站、绕过访问控制、自动填写表单或与招聘人员通信。用户仍自行查看职位链接并手动投递。

## 备选方案与选择

1. 直接按网页爬取所有来源：覆盖面大，但动态网页、反爬和维护成本高，且容易触碰访问边界。
2. 先接入可靠公开 API，再保留手动导入：可靠、可测试、对用户马上有用。**选择此方案。**
3. 只做手动粘贴：实现很快，但无法满足自动发现岗位的核心需求。

腾讯招聘公开 JSON API 作为首个自动来源。OfferBiu 保留探针：只有公开页面实际暴露可用岗位记录时才加入发现流程，否则在 UI 中明确标为“暂不可用”。用户也可粘贴公开岗位 URL 与 JD，或导入符合约定的 JSON 文件；这些输入不会触发外站登录或网络写操作。

## 架构

`packages/sources` 负责从公开来源取得原始记录；`packages/jobs` 负责把记录转换为统一岗位、计算稳定指纹、合并重复来源并给出可解释的状态；`packages/storage` 通过版本 2 迁移保存原始快照、规范岗位和来源链接。Fastify 只编排扫描和读取 API，React 只消费经 schema 验证的 API 数据。

```text
公开腾讯 API / 用户导入
  -> 原始记录快照
  -> Zod 校验与规范化
  -> URL + 公司/职位/地点 + JD 指纹去重
  -> SQLite jobs 与 job_sources
  -> 本地职位发现页面
```

## 数据与安全边界

- 每次扫描保存来源、抓取时间、受限长度的原始 JSON 快照和不含密钥的错误摘要。
- 不保存认证头、Cookie、用户简历、模型输出或任何外站登录信息。
- 对每个来源设置超时、页面大小上限和顺序执行；失败不会把已有岗位误标为过期。
- 岗位默认状态为 `unknown` 或 `active`；只有明确截止日期已过时才标记为 `expired`。
- 同一规范岗位可保留多个公开来源链接；不会因去重丢失用户可访问的原始链接。

## API 与界面

- `POST /api/jobs/scan/tencent`：请求一次公开腾讯 API，返回扫描统计。
- `POST /api/jobs/import`：接收一个已验证的 JSON 岗位或岗位数组，不会发起外部网络请求。
- `GET /api/jobs`：按关键词、城市、来源、状态分页列出岗位。
- `GET /api/jobs/:id`：读取单个岗位与全部来源链接。
- `GET /api/sources`：返回来源能力与 OfferBiu 当前探针状态。

界面提供“更新腾讯公开职位”按钮、透明的来源状态、关键词/城市过滤、岗位列表与详情抽屉。UI 不出现“立即投递”或会自动打开、填写招聘表单的控件；仅显示普通外部链接，用户主动点击才会离开本地应用。

## 错误处理与验收

- 网络失败、无效导入和数据库故障通过稳定错误码呈现，不回显原始 JD 或请求载荷。
- 重复扫描保持幂等；同一岗位不新增第二条规范记录。
- 新的确定性测试覆盖规范化、去重、状态、仓储迁移、API 和界面筛选；Playwright PDF 测试继续作为全量验证的一部分。
