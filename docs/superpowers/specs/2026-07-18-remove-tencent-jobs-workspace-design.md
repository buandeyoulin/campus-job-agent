# 删除腾讯专用公开职位栏目的设计

## 背景与目标

早期 Phase 0 为验证公开岗位抓取能力，加入了“发现校招与实习岗位”栏目和腾讯专用扫描链路。项目现在已经具备自建公司库、官方招聘来源同步、统一岗位存储、AI 匹配和人工投递进度，因此单公司专用栏目重复且会造成列表选择状态混乱。

目标是删除腾讯专用栏目和运行时链路，让所有岗位统一来自自建公司库中经过核验的公开招聘来源。人工投递边界保持不变。

## 方案比较

1. 只隐藏前端栏目：改动最少，但会遗留无入口 API、适配器和历史岗位，后续维护者仍可能误用。
2. 删除完整腾讯专用链路（采用）：删除前端、扫描 API、服务依赖、来源适配器和过时的 Phase 0 探针，并通过数据库迁移清理腾讯专用来源记录。
3. 把旧栏目改造成第二个通用岗位页：功能与 AI 求职工作台、自建公司库重复，会继续保留两个岗位入口。

采用方案 2，以最小范围完成真正的统一，不新增替代界面。

## 架构与数据流

- `App` 不再渲染 `JobsWorkspace`，也不再接收 `jobsApi`。
- 删除浏览器端腾讯扫描客户端和对应组件。
- `JobsService` 继续提供通用岗位查询、详情和受保护的本机导入能力；删除腾讯抓取、来源状态和不可用错误。
- `/api/jobs` 和 `/api/jobs/:id` 保留，供 AI 匹配、进度跟踪和其他界面读取；删除 `/api/jobs/scan/tencent` 与 `/api/sources`。
- 公司官网岗位继续通过 `/api/companies/jobs/sync` 写入统一岗位库。
- 删除腾讯来源适配器、fixture 和过时的 Phase 0 腾讯可行性探针。

## 数据迁移

新增幂等迁移，删除 `source = 'tencent'` 的 `job_sources`、`source_scans` 和只属于该来源的岗位记录。其他公开公司来源、手工导入岗位和求职进度不受影响。

如果历史腾讯岗位已被求职进度引用，为避免破坏用户记录，迁移保留该岗位本体，但移除腾讯来源关联；界面仍可在求职进度中看到历史快照，不能再通过腾讯扫描更新。

## 测试与验收

- 前端测试证明页面不再出现“发现校招与实习岗位”和“更新腾讯公开职位”。
- 路由测试证明腾讯扫描端点返回 404，通用岗位查询仍可使用。
- 迁移测试覆盖无引用腾讯岗位的清理和有求职进度引用岗位的保留。
- 全仓库搜索确认没有腾讯专用运行时代码。
- 运行 `npm run verify`，并在浏览器中确认自建公司库与 AI 求职工作台正常显示且旧栏目消失。

## 非目标

- 不重新设计 AI 求职工作台。
- 不改变公司官网适配器、岗位匹配算法或人工投递规则。
- 不删除通用岗位表、通用岗位查询 API 或已有非腾讯岗位。
